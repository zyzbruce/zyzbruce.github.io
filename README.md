# Bruce Zhang · 张严之 — Resume Site (v1)

Bilingual (简体中文 / English) static resume site. Pure HTML/CSS/JS — no build step, no external CDNs.

## File layout

```
index.html         Page structure + baked-in Chinese text (generated by build-static.js).
                   Elements carry data-i18n="key" / data-i18n-list="key" / data-email="key".
build-static.js    Re-bakes zh text from js/content.js into index.html (node build-static.js).
js/content.js      ALL bilingual text (one object: key -> { zh, en }). Edit text here.
js/main.js         Language logic (?lang=en|zh > localStorage("resume-lang") > default zh),
                   cross-fade on toggle, IntersectionObserver scroll-reveal (hidden state is
                   only added after JS runs), scroll-progress bar and nav scrollspy.
css/base.css       Mobile-first base styles (accent colour = --accent).
css/wide.css       Desktop tweaks, loaded via <link media="(min-width: 720px)">.
css/dark.css       Dark palette, loaded only with prefers-color-scheme: dark.
css/print.css      Print / "Save as PDF" layout (hides nav, contact, buttons).
css/effects.css    Motion & polish, screen only (media="screen"): hero blobs + entrance,
                   scroll-reveal, card hover/focus glow, timeline, nav highlight, lang cross-fade.
                   All disabled under prefers-reduced-motion; never applied to print.
favicon.svg        "BZ" initials icon.
screenshots/       Verification screenshots (not needed for deployment).
bundle-single.js   Builds ../resume-site-dist/bruce-zhang-resume.html (one offline file).
```

Private source write-ups live OUTSIDE the site root in `/workspace/resume-site-private/`
(never copy them into this folder or publish them). When deploying, you can also exclude
`screenshots/`, `README.md` and the build scripts; only index.html, favicon.svg, css/, js/ are needed.

## Single-file offline version

```
node build-static.js && node bundle-single.js
# -> /workspace/resume-site-dist/bruce-zhang-resume.html
```

Inlines all CSS (wide/dark/print become `@media` blocks), content.js + main.js and the favicon
(data URI). Double-click to open offline; the language toggle works (`?lang=en` too).

## Editing text

**Workflow:** edit `js/content.js` → run `node build-static.js` → reload.
`content.js` is the single source of truth. `index.html` ships with the Chinese text
already in place (works without JavaScript, readable by search engines); `main.js`
swaps text to English at runtime. If you skip the build step, the page still shows
your edits with JS on, but the no-JS / SEO version will be stale. The script is
idempotent and only rewrites text inside elements tagged with data-i18n /
data-i18n-list / data-email, plus `<title>` and the meta description.

- Change wording: edit the `zh` / `en` strings in `js/content.js`.
- Bullet lists are arrays (`*_list` keys); add/remove strings freely.
- Tech tags (`*_stack` keys) are one string separated by ` · `; each item becomes a pill.
- Add a new project: copy a `projN_*` block in `content.js`, then copy an `<article class="entry">`
  in the Projects section of `index.html` and update the keys.
- Contact email: `contact_email` key (used for both link text and `mailto:`). It also appears
  in the hero line in print only (`.print-only`).
- Work authorization line: `work_auth` key (hero + Contact).
- `og:*` meta tags in `index.html` are hand-written (not generated); edit them directly.

## Preview locally

```
cd resume-site
python3 -m http.server 8080
# open http://localhost:8080/  (English: http://localhost:8080/?lang=en)
```

## Deployment options (not done — v1 is local only)

- **GitHub Pages**: push the site files to a repo, Settings → Pages → deploy from branch root.
- **Netlify**: drag-and-drop the folder  in the Netlify dashboard, or connect a repo; no build command, publish dir = root.
- **Vercel**: import the repo as a static project; framework "Other", no build command.

Add an `og:image` and `og:url` meta tag once the final URL is known.
